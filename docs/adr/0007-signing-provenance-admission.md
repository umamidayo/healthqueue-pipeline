# 0007. Keyless signing, SLSA Build L3 provenance, admission-time verification

- Status: Accepted
- Date: 2026-10-25

## Context

The pipeline must align with SLSA and provide supply chain security. The core
question is: *can the cluster prove that the image it is about to run was
built by our pipeline, from our main branch, without modification?* Answering
it takes three things:

1. a signature binding the image digest to a builder identity,
2. **provenance** describing how, from what, and by whom it was built, generated
   so that the build steps themselves cannot forge it,
3. **verification** at the point of use, which fails closed.

Long-lived signing keys are a liability. They must be stored, rotated, and
protected from CI itself.

## Options considered

Signing:

| Option | Pros | Cons |
|---|---|---|
| **Sigstore keyless** (cosign + Fulcio + Rekor, GitHub OIDC) | No keys to manage; identity = workflow path + ref; public transparency log | Depends on the public Sigstore good instance; identities are verbose |
| cosign with a KMS key | No external dependency at verify time | Key management and rotation; the key is reachable from CI |
| Notary v2 / notation | OCI-native | Smaller ecosystem in Kubernetes admission |

Provenance:

| Option | Pros | Cons |
|---|---|---|
| **slsa-github-generator `generator_container_slsa3`** | Provenance generated in an isolated reusable workflow whose signing identity the build job cannot use, which is what SLSA Build L3 requires; verified by Kyverno today | Must be referenced by tag (not SHA); SLSA v0.2 predicate; legacy cosign storage format |
| GitHub artifact attestations (`actions/attest-build-provenance`) | First-party; SLSA v1 predicate; Sigstore bundles | L2 by default (L3 only through a reusable-workflow setup); in-cluster verification needs the newer Kyverno policy types |
| BuildKit `provenance: mode=max` | Free | Unsigned; generated by the same process that ran the build (L1) |

Verification point:

| Option | Pros | Cons |
|---|---|---|
| **Kyverno ClusterPolicy (`verifyImages`) at admission, plus the same checks in CI** | Fails closed at the last moment; CI pre-check means a reviewer never sees an unadmittable promotion | Admission webhook on the critical path; Kyverno 1.19 deprecates ClusterPolicy (see below) |
| Sigstore policy-controller | Purpose-built | Another controller; we already need Kyverno for other policy |
| Verify in CI only | Simple | The cluster trusts whatever lands in Git |

## Decision

- **Sign every pushed image** with cosign keyless. The identity is
  `https://github.com/<repo>/.github/workflows/ci.yml@refs/heads/main`.
- **Attach the CycloneDX SBOM** as an attestation with the same identity
  (ADR 0006).
- **Generate SLSA provenance** with `slsa-github-generator`'s container
  generator, **pinned to tag `v2.1.0`**. The generator verifies it was invoked
  by a tag ref. This is the documented exception to SHA pinning.
- **Verify twice:**
  - `scripts/ci/verify-image.sh` runs in CI after provenance and again before
    the production PR is opened.
  - `deploy/platform/policies/verify-images.yaml` enforces the same identities
    at admission for every Pod in a staging or production namespace. It also
    checks that provenance `configSource.uri` is this repo's `refs/heads/main`
    and `entryPoint` is `ci.yml`. A build from a fork, branch, or other
    workflow is rejected even if validly signed.
- `require-digest.yaml` additionally rejects tags and foreign registries in
  those namespaces.
- **The local environment is exempt.** Its image is built on the laptop,
  imported into minikube, and never signed. Signing is skipped rather than
  faked with a local key, so nobody confuses a local signature with a real one.
- **Legacy signature storage format, on purpose:** cosign v3 defaults to
  Sigstore bundles stored as OCI referrers. The SLSA generator still writes
  legacy `.sig`/`.att` tags, and `kyverno.io/v1` `verifyImages` verifies
  those. We sign with `--new-bundle-format=false --use-signing-config=false`,
  so every artifact for an image is in one format that one policy can verify.

### Amendment (found in local end-to-end testing): pinned Fulcio roots

Testing against a live cluster showed that **an image signed by CI was rejected
at admission** with `x509: certificate signed by unknown authority`, even
though `cosign verify` (and the CI `verify` job) accepted it.

- **Cause:** cosign v3 in legacy format writes signatures **without the
  certificate chain**. Kyverno's `ClusterPolicy` verifier does not fall back
  to Sigstore's `trusted_root.json` to find the intermediate. Enabling
  Kyverno's TUF client did not change this. The SLSA provenance passed only
  because the generator's older cosign embeds the chain.
- **Fix:** the policy pins Sigstore's public Fulcio root and intermediate
  (`keyless.roots`, one YAML anchor shared by all three attestors). These are
  the `fulcio_v1.crt.pem` / `fulcio_intermediate_v1.crt.pem` targets from
  Sigstore's TUF repository, both valid until 2031. Identity checks are
  unchanged: a policy expecting another repository or branch still rejects
  the image (tested).
- **Regression guard:** CI's `verify` job and the `promote` workflow now run
  `scripts/ci/verify-admission.sh`, which evaluates the real policies with the
  Kyverno CLI (the cluster's engine) against the built image. cosign alone is
  not a faithful proxy for admission.
- **Cost:** when Sigstore rotates the Fulcio CA, the pinned roots must be
  updated (docs/operations.md, recurring maintenance). The admission pre-check
  fails loudly when that happens. The ImageValidatingPolicy migration above
  removes the pin, because it verifies against the trusted root.

## Trade-offs and consequences

- **Kyverno 1.19 marks `kyverno.io/v1 ClusterPolicy` as deprecated** (the CLI
  prints this in `kyverno test`) in favour of `ImageValidatingPolicy`
  (`policies.kyverno.io`). It still works and is enforced here.
  Migration plan, one PR:
  1. Rewrite both policies as `ImageValidatingPolicy` / `ValidatingPolicy`.
  2. Switch cosign to bundle format (drop the two flags).
  3. Move provenance to GitHub artifact attestations if the generator has
     not adopted bundles.
  4. Update `verify-image.sh`.

  `kyverno test` in CI catches a removal on upgrade.
- Admission depends on reaching Rekor and the registry. If either is down,
  new pods in staging or production cannot start, while running pods are
  unaffected. This is the fail-closed choice. Kyverno caches verification
  results, which absorbs short blips.
- Keyless identities tie trust to the workflow file path. Renaming `ci.yml`,
  or moving the repo, invalidates every policy and is a coordinated change.
- The provenance proves *where* the image was built, not that the source was
  reviewed. That half is the Source track (branch rules + CODEOWNERS, see
  docs/slsa.md).

## Revisit when

- The Kyverno ClusterPolicy removal is scheduled (track Kyverno release notes).
- A private Sigstore instance is needed, for air-gapped clusters or to keep
  build metadata out of the public log. Then a private Fulcio/Rekor or a KMS
  key replaces keyless signing.
